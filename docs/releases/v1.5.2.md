# spoolbook v1.5.2 — sign-in required, and the lost features are back

**Released**: 2026-10-16

PATCH: brings back features the retired desktop and Blazor apps had, which were lost in the
move to the web app. That's a reversal of an accidental removal, not new capability, so PATCH. It
also ships the v1.5.1 security fix, which never went out as its own release.

Spec coverage: 100% of surfaces, 76% of FRs tested (62% at planned layer).

## Security (from v1.5.1)

- **Nothing is visible without signing in.** Your notebook used to be readable by anyone who
  could reach spoolbook (on the LAN or through a reverse proxy) without signing in. Now every
  page and API read needs a session; signed out, you see only the sign-in page (or first-run
  setup). Only the sign-in/setup routes and `/api/version` stay open. (#208)

## Restored

- **Colors.** **Filaments → Colors** lists every color with its swatch, name and hex: filter,
  sort, page, add, edit (renaming carries over to its filaments) and delete (refused while a
  filament uses it). (#177)
- **Multi-color filaments.** A color can have several hex codes (`#1A1A1A, #D4AF37`); its
  swatch splits into diagonal wedges, one per color. (#211)
- **Swatches everywhere.** Next to the filament in the filament, spool, profile and print
  lists, the print page, and the Print dialog's pickers. (#212)
- **Searchable filament picker.** Type any words of the brand, material, variant or color;
  options show swatches; arrows, Enter and Escape work. (#213)
- **Print outcome.** On a finished print, **Edit outcome** records the result, failure modes,
  notes, room temperature and whether the plate was clean. Prints are still only created by
  sending a job, so their settings are what was actually printed. (#164)
- **Profile versions as variants.** A profile's **Versions** panel lists every version; name
  one ("Winter 2026"), **Use this version** to switch which one you print with, and branch a
  new version from any of them. (#218)
- **Duplicate a profile** into a new, separate one. (#219)
- **Spool list:** brand, material, color and status columns; filters for brand, material,
  status and purchase dates; sortable; page size. (#214)
- **Prints list:** spool and outdoor temperature columns; filters for brand, material, printer
  and status; sortable; page size. (#215)
- **Profiles list:** scope (generic or which spool) and version columns; filters for brand,
  material and scope; sortable; page size. (#217)
- Spool, print and profile lists keep their filters, sort and page in the address, so refresh,
  back and shared links keep your view.
- **Plate stepping.** In the Print dialog, ‹ › step through a multi-plate project's plates,
  showing "n / N". (#216)
- **Projects from a link.** Paste a direct `.3mf` URL and **Fetch**, on the Projects page or
  in the Print dialog. A new project that looks like the next version of one you have asks
  "link it?". (#170)
- **Unsaved changes.** Leaving any edit form with unsaved changes asks first. (#220)

## Fixed

- Deleting a profile that a print used, or that a newer version builds on, now says why instead
  of failing silently.
- Deleting a profile version that isn't the one in use no longer leaves two versions in use.

## For developers

- Removed: `POST /api/prints`, `GET /api/prints/job-match` and `POST
  /api/prints/{id}/attach-job` — Prints are only created by sending a job. `PUT /api/prints/{id}`
  now takes only the outcome fields (status, failure modes, notes, room temp, clean plate).
- New: inventory endpoints with filters, sort and paging for spools, colors and profiles (and
  more filters on prints); profile version list, select, rename and duplicate; color
  create/edit/delete.
- Migration `0019` adds `prints.actual_room_temp_c`.
- CI: the hung-slicer timeout test no longer runs DB queries under a paused clock (it failed on
  slower runners with `PoolTimedOut`); a new test covers an unreachable slicer service → 502.
- Pages still have no browser-level tests (#180), so the restored screens are checked by type
  check and build only.

## Upgrading

No manual step — the migration runs on start. Pull the new image and restart:

```sh
docker compose pull && docker compose up -d
```

Anything that read the API without signing in (scripts, dashboards) now gets `401` and needs a
session cookie from `POST /api/login`.

Closes #208, #164, #170, #177, #211, #212, #213, #214, #215, #216, #217, #218, #219, #220.
