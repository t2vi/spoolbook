# spoolbook v1.5.0 — versioned profiles, AGPL licence, and a big bug sweep

**Released**: 2026-10-16

MINOR: new capabilities (profile versioning, spool picker on profiles, Source link) plus a large
batch of fixes found by mapping every feature to a written spec. Nothing breaking.

Spec coverage: 100% of surfaces, 80% of FRs tested (63% at planned layer).

## Highlights

- **Print profiles are versioned.** Once a print has used a profile version it's locked, so a
  past print always shows the settings it was really printed with. Open it and use **Save as new
  version** to keep your edits as the next version; the edit page shows which version you're on.
  Deleting the newest version makes the previous one current again.
- **Spool picker on profiles.** A profile can be generic (any roll of its filament) or specific to
  one spool — now set from the form, not only by import.
- **Licence is now AGPL-3.0-or-later** (was MIT). You can use, change and share spoolbook freely;
  if you run a modified version for other people, including over a network, you have to offer
  them its source. The sidebar has a **Source** link to the repository for that.

## Security

- **Printer access codes were readable by anyone on the LAN** through the open printer list.
  They're now write-only (the API only says whether one is set), saving a printer with the
  access code left blank keeps the stored one, and retrying the camera needs a signed-in editor.

## Fixed

- **Import (Settings → Data)** is all-or-nothing: a failure no longer leaves a half-imported
  install, and spool-specific profiles and project version chains keep pointing at the right
  rows after import.
- **Prints:** deleting a print with failure modes no longer fails; creating/updating one with an
  unknown status, failure mode, profile, spool, printer or project, or an end before its start,
  is refused instead of erroring or saving bad data; attaching a telemetry job checks it exists
  and isn't already attached elsewhere.
- **Send print** checks the profile and spool *before* starting the printer, so a bad choice can
  no longer start a job with no print recorded.
- **Weather:** prints shorter than an hour now get outdoor weather (the hour they started in was
  skipped); a slow weather service can no longer stall a printer's live connection at the end of
  a print, and the request gives up after 10 s.
- **Camera:** changing a printer's IP or access code, or deleting it, drops the old camera
  connection instead of reusing the stale one until restart.
- **Projects:** deleting a superseded version no longer fails, deleting the current one no
  longer hides the whole history, and the stored `.3mf` is removed; uploads and URL imports must
  be real `.3mf` files; version links can't loop; URL import (2 min) and re-slicing (10 min) time
  out instead of hanging, and URL import stops as soon as a file passes 100 MB.
- **Profiles:** saving no longer erases notes or the version name, no longer relabels an
  imported profile as Manual, and no longer drops its spool; an unknown filament or another
  filament's spool is refused; Bambu preset lookups time out after 30 s.
- **Filaments & spools:** deleting a filament that has profiles is refused with a reason instead
  of erroring; spools need a real filament and dates in order (purchased, opened, emptied).
- **Catalog sync** reports a failed fetch as a failure (and doesn't start the 24 h wait); it
  gives up after 30 s.
- **Settings:** out-of-range latitude/longitude is refused; the account page refuses a password
  under 8 characters or a taken username instead of silently ignoring it or erroring.
- **Telemetry cleanup:** the daily removal of old unmatched jobs now runs the tested code path
  and survives a database error.

## For developers

- Every product area now has a spec (`specs/001`–`008`) and `specs/COVERAGE.md` maps each
  requirement to its tests. Pages still have no browser-level tests (#180).
- Gitflow: PRs target `develop`; releases are cut from it (`docs/gitflow.md`).
- Two migrations run automatically: `0017` (profile version chain) and `0018` (drops two unused
  desktop-era settings columns).

## Upgrading

No manual step — migrations run on start. Pull the new image and restart:

```sh
docker compose pull && docker compose up -d
```
