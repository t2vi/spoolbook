# spoolbook v1.0.0 — Rust backend, .NET fully retired

**Released**: 2026-08-25

The planned end-state of the Rust backend port (own schema from day one, one real data migration
at cutover, .NET deleted outright — see `CLAUDE.md`'s Architecture section) is now live. That's
the version bump: not a stability claim about the codebase, but that the thing the whole port was
building toward has actually shipped.

---

## Highlights

- **The entire backend is now Rust** (`spoolbook-rs`: axum + sqlx + tokio) — `Spoolbook.Desktop`,
  `Spoolbook.Web`, and every other .NET/EF Core project are deleted outright, not deprecated.
  `spoolbook-rs` owns its own SQLite schema and migrations from scratch; it does not share a
  database file with the old EF Core app.
- **One real, one-time data migration** moved existing filaments/spools/print profiles/printers/
  projects/prints/settings from the EF Core SQLite file into `spoolbook-rs`'s own schema —
  including int→string enum translation (print status, ambient source, failure mode, profile
  source/slicer) and decimal-as-TEXT→REAL conversion for the ~140-field print profile. See
  "Upgrading" below — **this is a manual step existing installs must run**, not automatic.
- **Fixed a real auth bug found while retiring .NET**: the SvelteKit frontend had no `/login` page
  and no `logout()` API call — it was silently relying on .NET's server-rendered login form as a
  fallback. Left as-is, deleting `.NET` would have broken all sign-in. Now `spoolbook-rs` serves a
  proper `/api/login`/`/api/logout` and SvelteKit has its own login page.
- **New Docker image**: `spoolbook-rs/Dockerfile` (multi-stage: Node for the frontend, Rust for the
  backend, `debian:trixie-slim` runtime) replaces the old `Spoolbook.Web/Dockerfile`. Binds
  `0.0.0.0:5070` (was `127.0.0.1:8090` in dev-only `spoolbook-rs` builds before this release).
  `docker-compose.yml` and both GitHub Actions workflows (`docker-images.yml`, `tests.yml`) point
  at the new image/toolchain.
- **Startup filament-catalog auto-sync** ported to Rust — throttled to once/24h via
  `app_settings.last_filament_sync_at`, matching the old .NET behavior exactly (was previously
  manual-sync-only in `spoolbook-rs`).
- **Delete guards** (`has_spools`/`has_profiles`/`has_prints`) for Filament/Spool/PrintProfile/
  Printer deletion, ported from .NET, now enforced in `spoolbook-rs` too.

## Known gap

**Ambient weather auto-fetch (Open-Meteo) was not ported.** `ambient_temp_c`/
`ambient_humidity_pct` existed as an auto-fetched field on Print in the retired .NET backend;
`spoolbook-rs` leaves them manual-entry-or-null for now. Not silently dropped — documented in
`README.md` and `CLAUDE.md`.

## Upgrading

**This release changes the database file and the Docker image build. Existing self-hosted
installs must migrate data manually before upgrading, or they'll start from an empty database.**

1. Before pulling the new image, back up and locate your current data volume (the file the old
   `Spoolbook.Web` container used, typically the `spoolbook-data` Docker volume's
   `spoolbook.db`, or `~/Library/Application Support/spoolbook/spoolbook.db` for a local
   `dotnet run` dev instance).
2. Run the migration script against a copy of that file:
   ```sh
   python3 scripts/migrate-to-rust.py <path-to-old-spoolbook.db> <path-for-new-spoolbook-rs.db>
   ```
   Requires `sqlx-cli` (`cargo install sqlx-cli`) and Python 3 — it creates the target schema via
   `sqlx migrate run` (so `spoolbook-rs`'s own startup migration check doesn't panic on an
   already-populated-but-unbookmarked DB), then copies and converts every row. Prints row-count
   and foreign-key-integrity verification at the end — confirm it says `RESULT: PASS` before
   proceeding.
3. Put the resulting file where `docker-compose.yml`'s `spoolbook-data` volume expects it
   (`/data/spoolbook-rs.db` inside the container), then `docker compose pull && docker compose up
   -d`.

**Fresh installs**: the one-click installer (`install.sh`) is unaffected — a new install has no
old data to migrate, `spoolbook-rs` just creates an empty schema on first launch as normal.

**If you were running `Spoolbook.Desktop` or `Spoolbook.Web` directly** (`dotnet run`): that no
longer works at all, those projects are deleted. Use `spoolbook-rs` (`cargo run`, see README) or
the Docker image.
