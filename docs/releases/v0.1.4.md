# spoolbook v0.1.4 — NumericUpDown rollout, profile field dropdowns

**Released**: 2026-07-26

---

## Highlights

- **NumericUpDown everywhere applicable**: Spool weight, Print AMS humidity, and Print actual room temp are now spin-button numeric inputs instead of free-text fields with manual parse validation. In the profile field editor, `TextBoxWithUnit` gained a numeric mode (still shows the unit suffix) and now renders as `NumericUpDown` for the ~25 profile fields Bambu Studio itself shows as a spinner (temps, fan speeds, layer counts, etc.) — matched field-by-field against Bambu Studio's own UI rather than guessed. Spin buttons are compact and vertically stacked on the left, matching Bambu's own spinner style.
- **5 more profile fields are real dropdowns**: Scarf seam type, Z hop type, cooling slowdown logic, and both overhang cooling thresholds were free-text before — now proper dropdowns, with option values pulled directly from Bambu Studio's own `PrintConfig.cpp` source rather than guessed, so a typo can't produce an invalid preset value.
- **Pagination fix**: every inventory table's pager (Previous/Next, page counter, per-page dropdown) was silently non-functional — a `DataContext` self-binding on the `Pagination` control shadowed the bindings the parent view set on it. Fixed by binding through the control's element name instead.
- **`ShrinkPct` double-percent fix**: Bambu's raw preset format embeds a literal `%` in this field's value (e.g. `"100%"`), which combined with spoolbook's own unit-suffix display doubled up. Now stripped on import and re-added on export back to a linked preset file.
- **UI polish**: removed the accent-colored focus/hover ring and selected-cell outline that Fluent's default theme drew on `NumericUpDown` and `DataGridCell` — both were more distracting than useful in a dense settings grid. Fixed a regression from that work where `NumericUpDown`'s idle border had disappeared entirely.
- **Docs site no longer races the release build**: it used to redeploy on `release: published` in parallel with the per-OS asset uploads, so the Downloads page could go live before assets existed. Now waits for the asset-build workflow to finish via `workflow_run`.

## Upgrading

No schema changes, no data migration.
