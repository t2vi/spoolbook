# spoolbook v0.1.8 — Docker install, desktop app fully retired

**Released**: 2026-08-15

---

## Highlights

- **One-click Docker install**: `curl -fsSL https://raw.githubusercontent.com/t2vi/spoolbook/main/install.sh | bash` sets up `Spoolbook.Web` plus a new `spoolbook-slicer` service (BambuStudio, headless, for the re-slice-before-print feature) via Docker Compose, pulling pre-built images from GHCR — no local build, no .NET/Node toolchain needed on the host. Works the same on bare metal, a VM, or a Proxmox LXC (with nesting enabled) — anywhere Docker runs.
- **`Spoolbook.Desktop`'s Avalonia UI is gone.** It now exists only as the shared domain/data layer (`Features/`, `Data/`, `Migrations/`) that `Spoolbook.Web` builds on — not something you run directly anymore. The desktop release pipeline (`release.yml`, per-OS binary builds, the docs site Downloads page) is removed along with it.
- **Repo is now public** — the Docker images were already public build artifacts; keeping the source private bought nothing and blocked the curl-pipe-bash install pattern this release adds.
- **`spoolbook-slicer` CI-gated on latest-stable BambuStudio**: the image build fetches whatever BambuStudio currently tags as stable and runs a real slicing smoke test against it before the image ships — a BambuStudio update that breaks slicing fails CI instead of shipping silently.

## Upgrading

**Fresh installs**: use the one-liner above.

**Existing self-hosted installs** (pulling `main` + `npm run build` + restart): no change required, that path still works — Docker is a new option, not a replacement for it. No DB schema changes this release.

**If you were running `Spoolbook.Desktop` directly**: that no longer works at all — `dotnet run --project Spoolbook.Desktop` has nothing to launch. Move to the self-hosted web app (`Spoolbook.Web` + `spoolbook-web-svelte`, or the new Docker install).
