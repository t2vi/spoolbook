# spoolbook v1.1.0 — sending a print actually works, real accounts, ambient weather

**Released**: 2026-08-25

## Highlights

- **Sending a print to a real printer works end-to-end for the first time since the Rust port.**
  `send_print.rs` and `printer_mqtt.rs` had never been exercised against real hardware — both
  carried "unverified" comments. Live testing against a real Bambu P2S found and fixed two
  real bugs: the FTPS upload was silently failing this printer's `require_ssl_reuse` TLS check
  (fixed by linking `curl` against the system's own libcurl instead of a from-source-vendored
  OpenSSL build, which couldn't satisfy it), and the MQTT connection was dying the instant a real
  status report arrived because `rumqttc`'s default packet-size limit (10KB) was smaller than
  this printer's real payload (~14KB). Confirmed by actually sending and starting a real print.
- **Real user accounts, with optional Google sign-in.** Settings-UI-configured (no env vars) —
  argon2-hashed passwords, sessions, and an optional link-only Google OAuth flow. Replaces the
  single shared-secret cookie the Rust port launched with.
- **Ambient weather, auto-fetched.** Once a Print ends, `weather.rs` averages Open-Meteo's
  historical hourly readings over the print's actual duration and window — purely informational,
  never manually entered, never folds into profile recommendations.
- **Start a new profile from a Bambu Studio default**, or import your own saved `.json` preset —
  restores a picker lost in the .NET-to-Rust rewrite, sourced from `slicer-service`'s own already-
  bundled BambuStudio install rather than a second synced copy of Bambu's preset library.
- **Printer Model field** is now a dropdown of known Bambu models (X1E, X1 Carbon, P2S, P1S, P1P,
  A1, A1 mini) with room for a custom entry — this value already drove product-photo lookup and
  P2S-specific print behavior, so a typo here used to break both silently.
- New Supabase-inspired color theme (mint-green accent, softer radii).

## Fixed

- **Saving a Spool or Print with a numeric field crashed** ("`.trim is not a function`") — Svelte
  binds `<input type="number">` to an actual `number` at runtime even though the state was
  declared as a string, and `.trim()`-based blank-checking broke the moment a number replaced it.
- **The Filament picker was an unsearchable flat list of 3,500+ entries** — now a searchable
  dropdown (also reused for the new Bambu Studio default-preset picker above).
- **Print profiles could never actually be created or edited through the web UI** — the backend
  expected ~135 individually-typed top-level fields; the frontend's dynamic tabbed form (correctly)
  sends them all as one string dictionary instead. Every real Save 422'd since the Rust port
  shipped. Backend now parses the dictionary using the same field-name/type table that drives the
  form itself.
- Uploading a real sliced `.3mf` (anything over 2MB — i.e. most of them) failed with a misleading
  "Couldn't read the uploaded file" — axum's 2MB default request-body limit was never overridden.
- Re-slicing failed on Apple Silicon hosts with a Rosetta ELF-loading error — `docker-compose.yml`
  now pins the slicer service's container to `linux/amd64` (BambuStudio has no arm64 Linux build).

## Upgrading

No manual migration step this time — `spoolbook-rs` applies its own schema migrations
automatically on startup, same as always. Pull the new image and restart:

```sh
docker compose pull && docker compose up -d
```
